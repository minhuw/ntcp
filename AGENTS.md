# Agent instructions

1. You may generate documents for your own or other agents' use, but must never author documents intended for human readers.
2. Store agent-use documents, plans, drafts, and notes in `workbench/`. This directory is ignored by Git; do not force-add its contents or link to them from tracked human-facing documents.
3. Reserve `docs/` for human-facing documents. Do not place agent-generated documents there.
4. When discussing or listing packetdrill failures, omit accepted incompatibilities documented in `integration/packetdrill/README.md` from actionable failure lists unless explicitly requested. Apply this only when the observed failure matches the documented cause; report new causes as regressions. Preserve raw test results and totals, separating known incompatibilities from actionable failures when reporting counts.
5. Never implement production code solely to make a test pass. Every production mechanism, policy, parameter, and special case must have a concrete purpose and design justification independent of the test's expected result. RFC permission and improved pass counts alone are insufficient justification. Use tests to expose and verify real defects; do not add fixture-specific behavior, arbitrary constants, or unnecessary state machines to reproduce an expected trace. Shared implementations and configuration mappings must represent real capabilities or independently justified policies. Keep test infrastructure separate and do not present its changes as transport improvements. When a test expectation conflicts with an independently justified implementation, preserve the original result and document the difference instead of distorting production behavior.
6. User-facing READMEs must contain durable usage, design decisions, and compatibility behavior. Keep run totals, pass/fail inventories, diagnostic transcripts, investigation progress, and agent triage instructions in `workbench/`. Do not duplicate generated reports or manifests as README prose.
